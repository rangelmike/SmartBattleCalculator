# Pokemon domain

Pure/reusable battle mechanics belong here, not in components. Prefer `@smogon/calc` (Champions generation 0), `@pkmn/sets`, and `@pkmn/dex` over hand-written battle rules.

| Files | Contract |
| --- | --- |
| `types.ts`, `showdown-parser.ts`, `team-import.ts`, `team-hash.ts` | Normalize Showdown text into typed teams, validate before save, serialize, hash and manage own/opponent library membership. |
| `champions-data.ts`, `champions-learnsets.ts`, `team-validation.ts` | Champions availability and strict save validation; level 50 and Champions SP/EV limits are not standard 252/510 EV rules. |
| `team-stats.ts`, `champions-sprites.json`, `team-order.ts`, `team-search.ts` | Level-50/base stats, form/item visuals, member ordering and search/autocomplete helpers. |
| `damage-calculation.ts`, `hp-effects.ts`, `damage-observations.ts` | Damage, recoil/recovery and KO projection, field/state effects, opponent spread estimation. |
| `calculator-session.ts`, `battle-boosts.ts`, `battle-hp.ts`, `individual-set.ts` | Local battle lifetime, temporary stages/HP, common-set and deterministic individual defaults. |

The `champions-sprites.json` map is generated by `npm run sprites:refresh`; it records verified Showdown GIF filenames so rendering performs no per-Pokemon network search. This command queries an external index and rewrites the generated JSON, so run it only when updating sprites and review the diff.

Tests live next to source as `*.test.ts`. For a domain edit, run its focused test, `npm run typecheck`, and the full `npm run test` suite before release. Do not change damage or validation behavior solely to satisfy a UI expectation without checking Champions rules.
