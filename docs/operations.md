# Free-tier operations and failure responses

The browser app cannot extend Supabase or GitHub Pages quotas. The UI now distinguishes rate limits, quota failures, a read-only database, a paused project, and network outages. A failed common-set lookup uses a deterministic Pokemon set, and a full browser storage area leaves the current battle usable in memory with a warning. Personal team reads are paged in 200-row requests to avoid Supabase's per-response row cap. These are continuity measures, not capacity increases.

| Risk | Project response | Owner action |
| --- | --- | --- |
| Database growth | Team reads no longer silently stop at 1,000 rows; write failures explain read-only mode. | Check database size in Supabase Usage. At the Free plan's 500 MB database quota, Supabase can make the database read-only. Archive or delete data only after a verified export, or upgrade. Pagination still downloads the entire personal library, so accounts with many teams will need server-side filtered pagination before they become large. |
| Egress / monthly active users / Edge invocations | Popular-team search is paged; users get a service error if requests fail. | Monitor Usage and set alerts outside the app. Current Free allowances are 5 GB egress, 50,000 monthly active users and 500,000 Edge Function invocations. Avoid unbounded retry loops and remove the unused public `validate-signup-email` function after switching fully to Google. |
| Authentication provider | The app presents only Google sign-in, with a root-path OAuth return and a recoverable error for canceled sign-ins. | Verify Google is enabled and existing accounts keep their user IDs, then disable the Email provider in Supabase to prevent direct API password sign-ins. Do not disable new-user signups globally. Google availability and consent configuration remain external dependencies. |
| Inactivity pause | UI identifies a paused project but cannot resume it. | Watch owner email and Supabase Dashboard. Free projects with insufficient user database activity over seven days may pause; one login per week is **not** a guarantee. Resume in Dashboard, or use a paid plan if uninterrupted availability is required. |
| Data loss | Source code and schema migrations live in Git. | Free projects do not provide downloadable automatic backups. Schedule an authenticated Supabase CLI `db dump` to encrypted off-site storage, then test restores. Never put database dumps, service-role keys, or user data in GitHub Pages or the public repository. |
| GitHub Pages | The app is static; Supabase hosts auth and data operations. | Pages has a recommended 1 GB repository limit and a soft 100 GB/month site bandwidth limit. Check its terms before using it as a commercial SaaS host; migrate the frontend if those limits or policies no longer fit. GitHub Pages cannot run a server-side fallback for a Supabase outage. |
| Third-party assets and Pokepaste | Calculator math and local state do not require sprites or Pokepaste fetches. | Monitor availability and terms for Showdown sprite URLs and Pokepaste imports. If either becomes critical, provide an owned, licensed asset/import path. |
| Browser storage | Calculator warns if local session persistence fails and remains usable until the page closes. | The user must free browser storage or use a browser permitting local storage. Temporary battle data is not a backup. |

## Capacity signals to watch

- Supabase Dashboard Usage: database size, egress, monthly active users, and Edge invocations. Investigate sustained growth before reaching plan quotas; there is no reliable fixed number of profiles or teams because row size, indexes, auth metadata, and usage patterns vary.
- Team library latency and transferred bytes for accounts with many saved teams. The 200-row request size avoids truncation, but the current client still loads the full personal collection; move search, counts, and team viewer to server-side pagination before this becomes slow.
- Supabase project status and backup age. A successful export is not enough: periodically restore into a separate test project.
- GitHub Pages deployment/build health, site size, and monthly bandwidth. The frontend build can succeed while Supabase is paused or unavailable.
